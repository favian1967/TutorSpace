# TutorSpace — полное описание продукта

> Настольное приложение для Windows, в котором **преподаватель английского** составляет ученику **план заданий на неделю**,
> а **ученик** каждый день открывает свои задания, выполняет упражнения, повторяет слова и оценивает уроки.
> Всё хранится в **Microsoft SQL Server** (10 таблиц), аудиофайлы — **на диске** рядом с программой.

Этот документ — полный справочник. По нему можно ответить почти на любой вопрос: как что устроено, где что хранится,
почему сделано именно так и что будет в пограничных случаях. Если нужен быстрый старт — читайте первые два раздела.

## 1. Что это за продукт

**TutorSpace** — перенос веб-проекта [teacher_system](https://github.com/favian1967/teacher_system) (Django + React)
в одно десктопное приложение. Нет сервера, нет браузера, нет Telegram-бота: одна программа, одна база.

### Две роли

| Роль | Что делает |
|---|---|
| **Преподаватель** | Заводит учеников, составляет им недели заданий, добавляет упражнения и автоматические правила, проверяет ответы, пишет комментарии, ведёт аудиотеку, публикует «слово дня», сохраняет шаблоны недель, собирает недели из текста («песочница»). |
| **Ученик** | Видит задания на сегодня (будущие дни закрыты), выполняет упражнения (в т. ч. голосом), отвечает на мини-миссии, отмечает выполнение, оценивает уроки, повторяет слова карточками, ведёт личный словарь, может «заморозить» урок на завтра без потери серии. |

Оба входят **на одном компьютере** под своими логинами (как два аккаунта в одной программе).

### Главная идея в одном абзаце

Преподаватель составляет **неделю** (понедельник–воскресенье). В каждом дне — **задания** (видео/материал, описание,
мини-миссия, упражнения). Задание **открывается ученику только в свой день**. Ученик отвечает — ответы сохраняются
как **попытки**, пропуски проверяются автоматически, остальное читает/слушает преподаватель. **Правила** сами
реагируют на действия ученика («ошибся — повтори через неделю»). **Серия дней** мотивирует заходить каждый день,
**словарь с интервальным повторением** помогает запоминать слова.

## 2. Быстрый старт

### Требования

- Windows 10 или 11, 64-бит.
- **Microsoft SQL Server**, запущенный на этом же компьютере: полный (`MSSQLSERVER`), Express (`SQLEXPRESS`)
  или LocalDB. Проверить: `Win+R` → `services.msc` → служба «SQL Server (…)» — «Выполняется».
- Устанавливать .NET **не нужно** — он встроен в `TutorSpace.exe`.

### Запуск готовой программы (релиз 1.0.0)

1. Скопируйте файл **`Выпуск\TutorSpace\TutorSpace.exe`** куда удобно (например, в `C:\Program Files\TutorSpace`)
   и запустите его. Это один файл, установка не нужна.
2. При первом запуске программа сама найдёт SQL Server, создаст базу `TutorSpace` и откроет окно
   **«Создайте аккаунт преподавателя»**.
3. Зарегистрируйтесь как преподаватель — вы сразу войдёте в программу.
4. «Ученики» → «Новый ученик»: задайте ученику имя, логин и пароль — под ними он будет входить.
5. Составьте ученику неделю («Создать пустой план» → «Задание»), опубликуйте — ученик увидит задания в свои дни.

Готовых учётных записей и тестовых данных в программе **нет**.

### Сборка из исходников (для разработчика)

- Нужен **.NET 10 SDK** и Visual Studio 2022 17.14+ / 2026 (workload «Разработка классических приложений .NET»).
- Запуск: открыть `ivan.slnx`, **F5**; или `dotnet run --project ivan.csproj`.
- Выпуск релиза — см. §27.

### Если что-то не так

- Окно «Подключение к SQL Server» при старте → сервер не найден. Проверьте службу SQL Server или впишите имя сервера
  (например `.\SQLEXPRESS`), логин оставьте пустым для входа через Windows.
- Начать с нуля: удалить базу `TutorSpace` (SSMS или `DROP DATABASE TutorSpace;`) и папку `%LOCALAPPDATA%\TutorSpace\media`.

## 3. Технологии и зависимости

| Что | Чем сделано |

## 5. Архитектура: как устроен код

### Слои

```
UI (окна, экраны, диалоги)  →  Services (правила предметной области)  →  Data (EF Core, SQL Server)
```

- **UI** ничего не знает о SQL и почти не трогает `AppDbContext` напрямую — вызывает методы сервисов.
- **Services** — статические классы. Каждый публичный метод — одна законченная операция
  («сохранить задание», «принять попытку», «перенести урок»).
- **Data** — классы-сущности и `AppDbContext`.

### «Контекст на операцию»

Каждый метод сервиса открывает **свой** `AppDbContext` в `using` и закрывает его в конце:

```csharp
public static void DeleteRule(int ruleId)
{
    using var db = new AppDbContext();
    var rule = db.Rules.Find(ruleId);
    if (rule == null) return;
    db.Rules.Remove(rule);
    db.SaveChanges();
}
```

Никакого долгоживущего контекста, никаких фоновых потоков, никакого кэша. Настольному приложению с одним
пользователем за раз этого достаточно, и так не бывает «застрявших» данных.

### Как экран «подгружает» данные

Все экраны построены одинаково — **метод `Reload()` перестраивает экран целиком**:

1. Вызывает сервис, получает свежие данные (запросы с `AsNoTracking()` — только чтение).
2. Очищает контейнер (`_root.Children.Clear()`).
3. Строит элементы заново из кода (`Ui.Card(...)`, `Ui.Button(...)`, …).

После любого действия пользователя (кнопка, диалог) вызывается `Reload()`. Поэтому на экране **всегда актуальное
состояние базы** — нет рассинхронизации «на экране одно, в базе другое».

Сложные экраны грузят связанные данные сразу, одним «деревом»:

```csharp
db.WeekPlans
  .Include(w => w.Enrollment).ThenInclude(e => e.Student)
  .Include(w => w.Assignments).ThenInclude(a => a.Exercises).ThenInclude(x => x.Audio)
  .Include(w => w.Assignments).ThenInclude(a => a.Rules)
  .AsSplitQuery();   // несколько простых SQL-запросов вместо одного огромного JOIN
```

Это `PlannerService.FullPlans` — им пользуются план недели, экран «Сегодня», «Неделя» ученика и шаблоны.

Вкладки карточки ученика (План / Обзор / Ответы / …) **строятся заново при каждом открытии вкладки** —
данные всегда свежие.

### Почему экраны собраны из кода, а не в XAML

Экраны сильно зависят от данных (сколько дней, сколько упражнений, какой тип), поэтому их удобнее строить циклом
в C#. XAML используется для трёх окон-каркасов (`LoginWindow`, `TutorWindow`, `StudentWindow`) и темы (`Theme.xaml`).
Общие элементы — в `UI/Ui.cs`: `Ui.Text`, `Ui.Button(текст, действие, стиль, подсказка, иконка)`, `Ui.IconButton`,
`Ui.Card`, `Ui.Chip` (плашка), `Ui.IconBadge`, `Ui.Avatar`, `Ui.Ring` (кольцо прогресса), `Ui.Tile`, `Ui.Header`.

### Ошибки

- Ожидаемая ошибка пользователя (пустое поле, неверный пароль, попытки закончились) — исключение **`UserError`**
  с готовым русским текстом.
- `Ui.Button` оборачивает каждое действие в `Ui.Try`: любая ошибка показывается окном, программа не падает.
- Ошибки SQL Server переводятся в понятный текст (`Errors.Friendly`, см. §19).
- Непредвиденные ошибки ловит `App.DispatcherUnhandledException` и тоже показывает окном.

### Единое «сегодня»

Все даты «сегодня» берутся **только** из `Clock.Today` (`Data/AppPaths.cs`). Это дата компьютера,
без часовых поясов.

### Сессия

`Session.Current` — вошедший пользователь (статическое поле). `Session.User` — то же, но с ошибкой, если никто не вошёл.

## 6. Что происходит при запуске

`App.OnStartup` по шагам:

1. **Культура `ru-RU`** для всего: даты `28.09.2026`, русские названия месяцев, календарь `DatePicker` с понедельника.
2. **Папки на диске**: `%LOCALAPPDATA%\TutorSpace` и `…\media` (`AppPaths.Ensure`).
3. **База данных** (`DbSettingsDialog.EnsureDatabaseOrDetect`):
   - если есть `settings.json` или переменная `TUTORSPACE_DB` — подключается по ним;
   - иначе (первый запуск) **пробует по очереди** `.`, `.\SQLEXPRESS`, `(localdb)\MSSQLLocalDB` с входом Windows
     и **запоминает первый сработавший** в `settings.json`;
   - если найдена **база старого формата** (18 таблиц — есть `WeekPlans`/`StudentProfiles`/`Assignments`
     или колонка `Tasks.WeekPlanId`) — **ничего в ней не меняет** и просит указать другое имя базы
     (новая будет создана автоматически);
   - `EnsureCreated()` создаёт базу и таблицы, если их нет.
4. Если подключиться не удалось — окно **«Подключение к SQL Server»** с текстом ошибки. «Отмена» закрывает программу.
5. **Окно входа** (`App.ShowLogin`). В пустой базе сразу открыта регистрация преподавателя («Создайте аккаунт преподавателя»).
6. После входа открывается окно роли: `TutorWindow` или `StudentWindow`.
7. Ученик без анкеты сначала видит **анкету** («Давай познакомимся»); закрыл анкету — выход обратно ко входу.
8. «Выйти» закрывает окно роли и снова показывает окно входа. Закрытие окна крестиком завершает программу.

## 7. База данных — полностью

### 7.1. Как объяснить за 30 секунд

Есть **люди** (`Users`). Преподаватель **связан** с учеником (`TutorStudents`). Для ученика составляется **неделя**
(`Weeks`), в неделе **задания** по дням (`Tasks`), в задании **упражнения** (`Exercises`), ученик на них
**отвечает** (`Answers`). К заданию можно добавить **правило** (`Rules`). Ещё есть **словарь** ученика (`Words`),
**слово дня** (`WordOfDay`) и **аудиофайлы** (`Audio`).

Картинка: [`Демо/Схема БД.png`](Демо/Схема%20БД.png).

```
Users ──< TutorStudents >── Users
              │
              └──< Weeks ──< Tasks ──< Exercises ──< Answers >── Users
                                │           │            │
                                └──< Rules  └── Audio ───┘
Users ──< Words      Users ──< WordOfDay      Users ──< Audio
```

### 7.2. Общие правила хранения

| Что | Как |
|---|---|
| Ключи | `Id int IDENTITY` в каждой таблице |
| Строки | `nvarchar(max)`; с ограничением: `Users.Username`, `Words.Word`, `Weeks.Name` — `nvarchar(200)` (по ним уникальные индексы) |
| Перечисления (роль, тип упражнения…) | **Текстом** (`'Tutor'`, `'GapFill'`), `nvarchar(32)` — база читается глазами |
| Дата и время | `datetime2` **локального** времени компьютера, без часовых поясов |
| Даты без времени | `date` (`DateOnly` в C#): дата недели, дата слова дня, дата повторения |
| Мелкие списки | **JSON-строка** в колонке `...Json` (см. §7.4) |
| Удаление | каскадное, где это безопасно; остальное очищает код (см. §7.5) |
| Схема | создаётся `EnsureCreated()`; **миграций нет**: изменили модель — базу нужно пересоздать |

### 7.3. Все таблицы и поля

Обозначения: **PK** — первичный ключ, **FK** — ссылка, `?` — может быть пустым (NULL).

#### `Users` — люди (и преподаватели, и ученики)

| Поле | Тип | Смысл |

### 7.4. JSON-поля: что внутри

Пишутся `System.Text.Json`, имена полей как в C# (с большой буквы), кириллица без экранирования,
перечисления — **числами**, даты — ISO.

`Users.VisitsJson` — дни посещений:
```json
[{"Date":"2026-09-29","FirstSeenAt":"2026-09-29T11:38:02","LastSeenAt":"2026-09-29T14:02:11","Hits":3}]
```

`Weeks.CallQuestionsJson` — вопросы к созвону:
```json
[{"Id":1,"Text":"Что было самым трудным на этой неделе?","Order":1,"IsAsked":false,"CreatedAt":"2026-09-28T10:00:00"}]
```

`Weeks.LessonReviewsJson` — оценки уроков (`Comparison`: 0 лучше, 1 так же, 2 хуже; `Verdict`: 0 хорошо, 1 плохо):
```json
[{"DayIndex":1,"Comparison":2,"Verdict":null,"Reason":"Слишком быстрое видео","CreatedAt":"…","UpdatedAt":"…"}]
```

`Weeks.IntrosJson` — самопрезентации:
```json
[{"StudentId":2,"AudioId":7,"AttemptNo":1,"DurationSeconds":35,"CreatedAt":"…"}]
```

`Rules.FiresJson` — журнал срабатываний:
```json
[{"Id":1,"CreatedAssignmentId":42,"Detail":"«Смотрим отрезок про семью» закрыто → повтор через 7 дн.","IsSeen":false,"CreatedAt":"…"}]
```

`Exercises.ConfigJson` — настройки упражнения (все поля есть всегда, используются нужные типу):
```json
{"Template":"He ____ to school yesterday.",
 "Blanks":[{"Answers":["went","did go"],"Hint":""}],
 "SegmentStart":"13:23","SegmentEnd":"14:44",
 "Reference":["he has 10 kids","he lives in Texas"],
 "MinTheses":3,"MaxTheses":5,
 "MinWords":0,"SampleAnswer":"",
 "Transcript":"I'll be back",
 "AttemptsAllowed":null}
```

`Answers.AnswersJson` — ответы ученика:
```json
{"Blanks":["went"],"Results":[true],"Text":"","Theses":[],"Marks":[]}
```

Как с ними работает код: у сущности есть свойство-«обёртка» (`plan.CallQuestions`, `rule.Fires`, `user.Profile.Visits`…),
которое при чтении разбирает JSON в список, а при присваивании записывает обратно. **Геттер каждый раз возвращает новый
список**, поэтому в коде правило такое: взять список → изменить → присвоить обратно → `SaveChanges()`:

```csharp
var questions = plan.CallQuestions;
questions.Add(new CallQuestion { Id = …, Text = "…" });
plan.CallQuestions = questions;
db.SaveChanges();
```

Повреждённый JSON не роняет программу — читается как пустой список (`Json.Read`).

### 7.5. Связи и что происходит при удалении

| Связь | При удалении «родителя» |
|---|---|
| `TutorStudents.StudentId → Users` | каскад |
| `TutorStudents.TutorId → Users` | запрещено (NO ACTION) |
| `Weeks.TutorStudentId → TutorStudents` | каскад (удаляются недели ученика) |
| `Weeks.TutorId → Users` | NO ACTION |
| `Tasks.WeekId → Weeks` | каскад |
| `Tasks.RepeatOfId → Tasks` | NO ACTION, **ссылку обнуляет код** |
| `Exercises.TaskId → Tasks` | каскад |
| `Exercises.AudioId → Audio` | SET NULL (упражнение остаётся без аудио) |
| `Answers.ExerciseId → Exercises` | каскад |
| `Answers.StudentId → Users` | NO ACTION |
| `Answers.AudioId → Audio` | NO ACTION, **ссылку обнуляет код** |
| `Rules.TaskId → Tasks` | каскад |
| `Words.StudentId → Users` | каскад |
| `WordOfDay.TutorId → Users` | каскад |
| `Audio.OwnerId → Users` | NO ACTION |

**Почему часть связей NO ACTION.** SQL Server запрещает каскады, которые доходят до одной таблицы разными путями
(и ссылки таблицы на саму себя). Поэтому `AppDbContext.SaveChanges` перед удалением недель/заданий/аудио
сам обнуляет «висячие» ссылки: `Tasks.RepeatOfId` на удаляемые задания и `Answers.AudioId` на удаляемое аудио.
Всё это — в одной транзакции.

Ссылки внутри JSON (например, `CreatedAssignmentId` в журнале правил, `AudioId` в самопрезентации) база не проверяет.
Код к этому готов: удалённое задание в журнале просто не показывается, самопрезентация с удалённой записью перестаёт
считаться.

**Пользователей из интерфейса удалить нельзя** — только «отключить» ученика у преподавателя.

### 7.7. Подключение к базе

- Строка по умолчанию: сервер `.`, база `TutorSpace`, **вход Windows** (Integrated Security), `TrustServerCertificate=True`,

- Хранится в `%LOCALAPPDATA%\TutorSpace\settings.json`:

  Пустой `Username` — вход Windows; иначе вход SQL Server по логину и паролю (**пароль хранится открытым текстом**).

- Изменить в программе: окно входа → «Настройки подключения к БД». Кнопка «Подключиться» сначала проверяет

## 8. Аудио: хранение, запись, воспроизведение

### Где лежит звук

- **Файлы** — в папке `%LOCALAPPDATA%\TutorSpace\media\<Id владельца>\<случайное имя>.<расширение>`,
  например `…\media\1\3f2a9c0b7d6e4f1a8b2c3d4e5f6a7b8c.mp3`.
  Имя — новый GUID, поэтому файлы не конфликтуют и имя не угадать.
- **В базе** (таблица `Audio`) — только **относительный путь** `StoredPath`, название, расшифровка, источник,
  исходное имя файла, размер, длительность, владелец и тип (клип преподавателя / запись ученика).
- Полный путь собирается на лету: `media` + `StoredPath` (`MediaAsset.FullPath`).

Почему не в базе: аудио тяжёлое, база растёт и медленнее бэкапится; файл на диске проще проигрывать и проверять.

### Загрузка файла (аудиотека, «Загрузить файл…»)

`MediaService.Import`:
1. Проверки: файл существует, **не больше 15 МБ**, не пустой.
2. Копирует файл в `media\<владелец>\<GUID>.<расширение>` (оригинал не трогается).
3. Если длительность неизвестна — узнаёт её через Windows MCI (`AudioPlayer.ProbeDuration`).
4. Создаёт строку в `Audio`. Если запись в базу не удалась — **копия удаляется**, мусор не остаётся.

Форматы в окне выбора: `mp3, wav, m4a, wma, aac, ogg` (и «Все файлы»). Проигрываются те, что умеет Windows Media.

### Запись с микрофона

`AudioRecorder` (через `winmm.dll`, команды MCI):
- формат записи — **WAV, 16 бит, моно, 22 050 Гц**;
- запись идёт во временный файл `%TEMP%\tutorspace_<GUID>.wav`, после остановки он импортируется как обычный файл
  (см. выше) и временный файл удаляется;
- максимум: **300 секунд** (5 минут — столько WAV помещается в 15 МБ), для самопрезентации — **60 секунд**;
  по достижении лимита запись останавливается сама;
- во время записи на кнопке «Остановить» и счётчик «Идёт запись… 0:12 / 5:00»;
- нет микрофона — сообщение «Ошибка звука: … (проверьте микрофон)».

Элемент интерфейса — `UI/Controls/RecorderPanel`: кнопка «Записать / Остановить» и (где разрешено) «Загрузить файл…».

### Воспроизведение

`AudioPlayer` — **один** WPF `MediaPlayer` на всю программу: новое «Прослушать» останавливает предыдущее,
кнопка ■ — остановить. При переходе между экранами звук останавливается. Файл не найден на диске —
сообщение «Аудиофайл не найден на диске».

### Где используется аудио

| Где | Что |
|---|---|
| Аудиотека преподавателя | клипы (`Source = TutorClip`) с расшифровкой и источником |
| Упражнение «Повторить за оригиналом» | прикреплённый клип (`Exercises.AudioId`); его расшифровка — «оригинал» |
| Голосовые ответы ученика | запись (`Source = StudentRecording`), ссылка `Answers.AudioId` |
| Самопрезентация недели | запись, ссылка в `Weeks.IntrosJson` |

### Удаление аудио

Удаление в аудиотеке убирает **и строку, и файл**. Упражнения, где клип был прикреплён, остаются без аудио;
у попыток ученика ссылка обнуляется (преподаватель увидит «Аудио удалено»); самопрезентации с этой записью
перестают отображаться и считаться.

## 9. Пользователи, пароли, вход, роли

### Пароли

- Хэш **PBKDF2-SHA256**, **100 000 итераций**, случайная **соль 16 байт**, хэш 32 байта.
- Строка в базе: `pbkdf2$100000$<соль base64>$<хэш base64>`.
- Проверка сравнивает хэши за постоянное время (`FixedTimeEquals`). Повреждённый хэш = «неверный пароль», не сбой.
- Пароль нельзя восстановить: забыли — преподаватель задаёт ученику новый («Сбросить пароль»).

### Ограничения

| Поле | Правило |
|---|---|
| Логин | 3–50 символов, уникальный **без учёта регистра** (`Tutor` = `tutor`) |
| Пароль | 4–200 символов |
| Имя | до 150 символов |

### Вход

Логин ищется без учёта регистра, пароль проверяется по хэшу. При входе **ученика** записывается посещение
(`Users.VisitsJson`: дата, первый/последний вход, число входов за день).

### Регистрация и ученики

- **Преподаватель** регистрируется сам в окне входа («Зарегистрировать преподавателя»).
- **Ученика** создаёт преподаватель («Новый ученик»): создаётся пользователь + связь `TutorStudents` одним действием.
- **«Прикрепить»** — привязать уже существующего ученика (например, от другого преподавателя) по логину.
  Если он уже ваш — «Этот ученик уже у вас»; если был отключён — включается обратно.
- **«Отключить»** — ученик пропадает из списков, его недели не видны ему по этой связи, данные целы. «Вернуть» — обратно.
- Удаления пользователей в программе нет.

## 10. Недели и задания

### Неделя

- Всегда начинается с **понедельника** (`StartDate`), дни — `DayIndex` 0…6.
- Одна неделя на ученика и понедельник (у каждого преподавателя своя).
- **Публикация**: пока неделя не опубликована, ученик не видит из неё ничего. Кнопка «Опубликовано/Опубликовать» в плане.
- **Созвон-разбор**: дата `ReviewAt`, по умолчанию — воскресенье.
- **Приватные заметки** видит только преподаватель.
- **Вопросы к созвону**: чек-лист, отмечаются во время созвона.

### Когда задание открывается ученику

```
Дата открытия = понедельник недели + DayIndex + DeferredDays
Задание открыто, если неделя опубликована И дата открытия ≤ сегодня
```

(`Assignment.ReleaseDate`, `Assignment.IsUnlockedFor`). Будущие задания ученик видит только как «N заданий откроются дд.мм».
Невыполненные задания прошлых дней (этой и прошлой недели) попадают в блок **«Не доделано»** на экране «Сегодня».

### Поля задания и проверки

- Заголовок обязателен (до 200), описание до 20 000, миссия до 300, минуты 0–600.
- **Ссылка** (`ResourceResolver.Normalize`):
  - только `http://` или `https://` — ссылка вида `C:\Windows\cmd.exe` или `javascript:` будет отклонена
    (иначе Windows запустила бы её по клику);
  - без схемы (`youtu.be/…`) — автоматически добавляется `https://`;
  - до 2000 символов.
- **YouTube распознаётся сам** (`youtube.com/watch?v=`, `youtu.be/`, `/embed/`, `/shorts/`, `/live/`):
  сохраняются ID видео и адрес превью. Кнопка у ученика — «Смотреть видео». Другой сайт — «Открыть», в превью — домен.
  **Программа никогда не ходит по ссылке сама** — только открывает её в браузере по клику.
- Отрезок видео в тезисах открывается с нужной секунды: к ссылке YouTube добавляется `&t=<секунды>`.

### Мини-миссия

Короткое задание к материалу. Виды и текст по умолчанию:

| Вид | Текст |
|---|---|
| Поймать новые слова | «Поймай 3 новых слова и запиши их» |
| Ответить одним предложением | «Ответь одним предложением: о чём это было?» |
| Записать голосовое | «Запиши голосовое на 15 секунд» |
| Пересказать своими словами | «Перескажи своими словами в 2–3 предложениях» |
| Своя формулировка | — |

**Если у задания есть миссия, но нет упражнений — закрыть задание без ответа на миссию нельзя.**

### Операции с заданиями (план недели преподавателя)

| Действие | Что делает |
|---|---|
| «Задание» / пунктир «Добавить» в колонке дня | новое задание (сначала сохранить, потом добавлять упражнения и правила) |
| Клик по карточке | открыть и редактировать; смена дня сбрасывает «заморозку» |
| Галочки + «Переместить» | перенести выбранные на выбранный день (заморозка сбрасывается) |
| «Удалить выбранные» | удалить с упражнениями и ответами (с подтверждением) |
| «На день раньше / позже» | сдвинуть **все** задания недели; если какое-то выйдет за пределы недели — **сдвиг отменяется** с объяснением |
| «Копировать» | скопировать неделю другому ученику / на другую неделю |
| «В шаблон» | сохранить неделю как шаблон |
| «Удалить план недели» | удалить неделю целиком |
| «Все недели…» | перейти к любой неделе ученика |

Порядок заданий в дне — поле `Order` (новое задание — в конец дня).

## 11. Упражнения: пять типов и их проверка

| Тип (`Kind`) | Название | Как проверяется |
|---|---|---|
| `GapFill` | Вставить пропущенные слова | **автоматически** |
| `OpenAnswer` | Ответить на вопрос | читает преподаватель |
| `Theses` | Тезисы по отрезку видео | ученик сам сверяет с ключом |
| `Speaking` | Повторить за оригиналом | слушает преподаватель |
| `Monologue` | Голосовой монолог | слушает преподаватель |

### Попытки

- Каждая отправка — **новая попытка** (строка `Answers`), история видна и ученику, и преподавателю.
- Лимит попыток: поле «Сколько попыток» (`ConfigJson.AttemptsAllowed`). Пусто: для голосовых — **3**,
  для остальных — без ограничений. `0` — без ограничений.
- Исчерпал — «Попытки закончились», форма ответа пропадает.
- Ответ принимается только если задание уже открылось и оно этого ученика.

### Пропуски (`GapFill`)

Разметка в тексте упражнения:

```
He {{went|did go::go}} to school yesterday.
```

- `{{ … }}` — пропуск;
- `|` — несколько правильных вариантов;
- `::` — подсказка (показывается серым рядом с полем и во всплывающей подсказке).

При сохранении текст разбирается (`ExerciseText.ParseGaps`) в шаблон `He ____ to school yesterday.`
и список пропусков — он хранится в `ConfigJson.Template` / `Blanks`. В окне упражнения есть **живое превью**
«Как увидит ученик». Ошибки разметки ловятся сразу: нет ни одного пропуска, незакрытые или вложенные скобки,
пустой ответ. Четыре подчёркивания в самом тексте заменяются на три, чтобы не спутать с пропуском.

**Проверка ответа** (`CheckGapFill`): ответ и варианты нормализуются — регистр не важен, лишние пробелы схлопываются,
знаки препинания по краям убираются, «умные» кавычки `’‘` становятся `'`. Пропуск засчитан, если нормализованный
ответ совпал с любым вариантом. Итог — «N из M», поля подсвечиваются зелёным/красным, после попытки показывается ключ.

### Ответ на вопрос (`OpenAnswer`)

- Можно задать **минимум слов** (0–500); короче — «Ответ короче N слов».
- **Пример ответа** ученик видит только после своей попытки.
- **Подстановка слов ученика**: в тексте вопроса `<<word>>`, `<<translation>>`, `<<example>>` заменяются на слова из
  его словаря (ещё не выученные, по порядку: каждый `<<word>>` берёт следующее слово, `<<translation>>`/`<<example>>` —
  от текущего). Например «Составь предложение со словом <<word>> (<<translation>>)».

### Тезисы (`Theses`) — в два шага

1. Ученик открывает отрезок видео (кнопка «Открыть отрезок 13:23–14:44», YouTube откроется с нужной секунды)
   и пишет тезисы по одному на строку. Количество — между «Мин.» и «Макс.» (по умолчанию 3–5).
2. После отправки видит **ключ преподавателя** и сам **галочками отмечает**, какие тезисы совпали по смыслу.
   «Совпало N из M» — это и есть результат.

Таймкоды: `13:23` или `1:02:11`; неверный формат не даст сохранить упражнение.

### Повторить за оригиналом (`Speaking`)

Прикрепляется клип из аудиотеки. Ученик слушает «Послушать оригинал», записывает себя (до 3 попыток),
после попытки видит текст оригинала (расшифровка клипа или поле «Текст оригинала»). Если клипа нет, а текст есть —
текст показывается сразу: «Произнеси: «…»».

### Голосовой монолог (`Monologue`)

Тема + запись голосового. Можно записать с микрофона или загрузить файл.

### Что видит преподаватель

Вкладка **«Ответы»**: все попытки ученика (новые сверху), задание, ответ в читаемом виде (`+ went; − goed — 1/2`),
кнопки «Запись ученика» / «Оригинал», поле **«Ваш комментарий»**. Оценок нет — **только комментарий**,
ученик увидит его под своей попыткой. Фильтр «Только без комментария».

## 12. Автоматические правила

Правило = «**когда** → **что сделать**». Срабатывают **только в ответ на действие ученика**, никаких таймеров.

| Когда (`Trigger`) | Условие |
|---|---|
| Ошибся в упражнении | результат попытки **ниже** порога, % |
| Справился с упражнением | результат **не ниже** порога, % |
| Закрыл задание | ученик отметил задание выполненным |

Процент попытки: `Score / MaxScore × 100`; если проверять нечем (`MaxScore = 0`) — считается 100%.

| Что сделать (`Action`) | Эффект |
|---|---|
| Повторить задание через N дней | создаётся **копия задания** (с упражнениями, без ответов) на дату «сегодня + N»; если недели на ту дату нет — создаётся неделя «Повторы»; у копии плашка «повтор» и ссылка `RepeatOfId` |
| Отметить преподавателю | только запись в журнал (с заметкой) |

- **«Сработать только один раз»** — после первого срабатывания правило молчит.
- **«Правило включено»** — выключенное не срабатывает.
- **Журнал** (`Rules.FiresJson`) — вкладка «Автоматика»: когда, что случилось, какое правило, какое задание создано.
  Новые отмечены «новое», кнопка «Отметить всё прочитанным». Число новых — в «Обзоре».
- Ошибка внутри правила **не мешает** сохранению ответа ученика (`RuleService.SafeEvaluate`).
- Из песочницы строка `повтор: 7` создаёт правило «Закрыл задание → повтор через 7 дн.».

## 13. Выполнение, серия дней, заморозка, оценки уроков, самопрезентация

### Выполнение задания

«Отметить выполненным» / «Снять отметку о выполнении» / «Сохранить ответ» (сохраняет ответ на миссию и комментарий,
не меняя отметку). Данные — в колонках `Tasks` (`IsCompleted`, `CompletedAt`, `MissionResponse`, `StudentComment`).
Отметка может запустить правило «Закрыл задание».

### Серия дней

- Засчитывается, когда ученик **выполнил хоть что-то** за день (первая отметка «выполнено» за день).
- Выполнил вчера и сегодня — серия +1; пропустил день — серия начинается с 1.
- Если ученик пропал (последняя активность раньше вчерашнего дня), показывается **0**, а не старое значение.
- Хранится лучшая серия (`LongestStreak`).

### Заморозка («Не успеваешь сегодня?»)

- Переносит **весь сегодняшний урок** (все задания дня) **на завтра** (`DeferredDays = 1`) и **сохраняет серию**.
- Только сегодняшний урок, только на 1 день, **не в воскресенье** (неделя не удлиняется),
  нельзя, если что-то из урока уже выполнено или урок уже переносили.
- **1 заморозка в неделю**. Преподаватель видит плашку «перенесено на дд.мм».

### Оценка урока

Появляется у открытого дня с заданиями:
- **первый урок недели** — «Хорошо / Плохо»;
- **следующие** — «Лучше предыдущего / Такой же / Хуже предыдущего» (сравнение с предыдущим днём с уроками).

При «Плохо» / «Хуже» **обязательно написать, что не понравилось**. Повторная оценка заменяет прежнюю.
Хранится в `Weeks.LessonReviewsJson`. Преподаватель видит оценку на доске недели (красная/зелёная плашка),
во вкладке «Оценки уроков» (таблица) и в «Обзоре» (последняя оценка, число жалоб).

### Самопрезентация недели

Включается галочкой в настройках недели. Ученик записывает рассказ о себе **от 30 до 60 секунд**
(допуск ±2 с), **до 3 попыток** в неделю, по вопросам «Кто ты? Где живёшь? О чём мечтаешь? Чем занимаешься?».
Хранится в `Weeks.IntrosJson` (ссылка на запись в `Audio`). Преподаватель слушает попытки в настройках недели.

## 14. Словарь, повторение слов (SM-2), слово дня

### Словарь

Слово + перевод (обязательны) + пример. Слово уникально у ученика (без учёта регистра). Поиск по слову и переводу,
фильтры «Все / К повторению / Учу / Выученные», «Уже знаю» / «Вернуть в изучение», правка, удаление.
Новое слово ставится на повторение **сегодня**.

### Повторение (алгоритм SM-2 с четырьмя ответами)

Карточка: слово → «Показать перевод» → четыре кнопки, под каждой — через сколько будет следующий повтор.

| Кнопка | Интервал | Лёгкость (EaseFactor) |
|---|---|---|
| **Снова** | сегодня (слово вернётся в конец текущей сессии); серия повторений обнуляется, «провалов» +1 | −0.20 |
| **Трудно** | max(текущий + 1, текущий × 1.2) | −0.15 |
| **Хорошо** | 1-й раз — 1 день, 2-й — 6 дней, дальше текущий × лёгкость | 0 |
| **Легко** | как «Хорошо», но × 1.3 (минимум +1 день) | +0.15 |

- Лёгкость ограничена 1.3–3.0 (начальная 2.5), интервал 1–365 дней.
- Интервал ≥ **180 дней** — слово считается **выученным**.
- Статус: `New` (не повторялось), `Learning`, `Mastered` (выучено).
- В очереди — слова, у которых дата повтора наступила, самые давние первыми.

### Слово дня

Преподаватель публикует слово на дату (одно на дату, повторное сохранение заменяет). Ученик видит **самое свежее слово
на сегодня или раньше** от любого своего активного преподавателя и может добавить его в словарь одной кнопкой.

## 15. Шаблоны недель, копирование, песочница

### Как неделя «кладётся» ученику

Все способы создать неделю из готового (шаблон, копия, песочница) работают через одну функцию
`TemplateService.Materialize`: неделя описывается данными (`WeekPayload` — задания, упражнения, правила, вопросы)
и «раскладывается» в базу. Если на ту неделю у ученика уже есть задания — программа спросит, заменить ли их.
Ссылки нормализуются, упражнения с ошибками пропускаются, аудио берётся, только если оно из аудиотеки этого преподавателя.

### Шаблоны

- **Шаблон — это неделя без ученика** (`Weeks.IsTemplate = 1`) с именем и описанием. Её задания и упражнения —
  обычные строки `Tasks` / `Exercises`.
- Создать: «План недели» → «В шаблон» или «Песочница» → «Сохранить как шаблон…». Шаблон с тем же именем перезаписывается.
- Шаблон — **снимок**: дальнейшие правки исходной недели его не меняют.
- Применить: «Шаблоны недель» → «Применить к ученику…» (ученик + любой день недели — берётся её понедельник)
  или в пустой неделе «Применить шаблон…». Счётчик «применён N раз».
- Правила переносятся только включённые; ответы, выполнение, оценки — никогда.

### Копирование недели

«Копировать» → ученик + неделя. То же, что шаблон, только без сохранения шаблона. В пустой неделе есть
«Скопировать с прошлой недели».

### Песочница — неделя из текста

Удобно вставить неделю, написанную в чате с нейросетью. **Разбор ничего не сохраняет** — сначала превью,
потом «Установить неделю ученику…» или «Сохранить как шаблон…».

Формат:

```
# ПН
## Смотрим отрезок про семью
ссылка: https://www.youtube.com/watch?v=dQw4w9WgXcQ
время: 15
миссия: поймай 3 новых слова
описание: Смотри без субтитров, потом сверимся.
повтор: 7
### пропуски
He {{went|did go}} to school yesterday.
### вопрос
What does he do for a living?
### тезисы 13:23-14:44
- he has 10 kids
- he lives in Texas

# СР
## Произношение
### произношение
текст: I'll be back

# ПТ
## Итоги недели
### монолог
Расскажи, что нового ты узнал за неделю.
```

| Строка | Значение |
|---|---|
| `# ПН` | день: `пн/понедельник/mon/monday/1/день 1` и т. п. для всех дней |
| `## Заголовок` | новое задание |
| `### тип` | упражнение: `пропуски/gap`, `вопрос/ответ/question`, `тезисы/theses`, `произношение/speaking`, `монолог/голосовое/monologue` |
| `### тезисы 13:23-14:44` | таймкоды отрезка прямо в заголовке |
| `ссылка:` `время:` `миссия:` `описание:` `повтор:` | поля задания (есть английские синонимы `url`, `time`, `mission`…) |
| `текст:` `подсказка:` `образец:` `аудио:` | поля упражнения (текст оригинала, инструкция, пример ответа, ID клипа) |
| `- пункт` | в тезисах — ключ преподавателя |
| остальные строки | текст упражнения или описание задания |

Парсер прощает ошибки: непонятное превращается в **предупреждение** и разумную догадку (неизвестный тип — вопрос,
неизвестный день — предыдущий, пропуски без `{{}}` — предупреждение, пустое упражнение пропускается,
неверный таймкод убирается).

Боковая панель: **Сегодня · Неделя · Повторение слов · Мой словарь · Профиль**, внизу «Выйти».

Иконка, заголовок, «15 мин · Понедельник, 28.09», плашки статуса; описание; блок материала с кнопкой

Шапка недели (название, преподаватель, «выполнено N из M», процент, полоса прогресса, дата созвона), самопрезентация,

## 22. Тестирование и проверка релиза

Перед выпуском 1.0.0 программа проверена тремя способами. Тестовый код в программу **не входит** —
проверки живут отдельно и работали на отдельных тестовых базах, которые потом удалены.

1. **Большой сценарий через настоящие окна** (81 проверка, релизная сборка): программа запускается, тест находит кнопки
   по тексту, нажимает, заполняет поля и диалоги (в т. ч. вложенные), отвечает на **настоящие окна сообщений Windows**
   и проверяет результат в базе. Сценарий: регистрация → ученики → план недели (все 5 типов упражнений, правила,
   перенос, сдвиг, публикация, настройки, вопросы, шаблоны, копирование, пустая неделя) → шаблоны и песочница →
   аудиотека (в т. ч. реальный микрофон) и слово дня → смена пароля → ученик (анкета, упражнения, миссия,
   выполнение, оценка урока, самопрезентация, неделя, повторение, словарь, профиль) → проверка работы ученика
   преподавателем. Отдельно — **в базе ровно 10 таблиц**.
2. **Прогон на всех 7 днях недели** (понедельник–воскресенье) — логика открытия заданий, «Не доделано»,
   оценки уроков сравнением и заморозки зависит от дня недели.
3. **Проверка опубликованного `TutorSpace.exe` снаружи** через Windows UI Automation (16 проверок) — как пользователь:
   запуск → регистрация преподавателя → новый ученик → план недели → задание с упражнением → слово дня → выход →
   вход ученика и анкета → ответ «Всё верно» → «выполнено» → оценка урока → словарь → закрытие программы.

Не автоматизированы: открытие ссылки в браузере, стандартное окно выбора файла Windows, щелчки в выпадающем календаре.

Папка `Скриншоты/` — снимки экранов из прогона на тестовой базе (данные на них тестовые).

## 24. Ограничения и известные особенности

- **Одна программа — одна база на компьютере.** Сетевой одновременной работы нескольких людей нет
  (хотя сервер можно указать сетевой — программа будет работать, но без учёта одновременных правок).
- **Миграций нет**: при изменении модели данных нужна новая база; базу старого 18-табличного формата программа не трогает и просит указать другое имя.
- «Сегодня» — **дата компьютера**, часовых поясов нет.
- Пароль SQL Server (если используется вход SQL) лежит в `settings.json` открытым текстом.
- Аудио хранится файлами: при переносе на другой компьютер нужно переносить и базу, и папку `media`.
- Нет Telegram-бота, почты, приглашений по ссылке и JWT из веб-версии — ученика создаёт преподаватель.
- Ссылки программа только открывает в браузере; превью YouTube — адрес картинки, сама картинка не загружается.
- Заморозка — 1 раз в неделю и не в воскресенье; сдвиг недели невозможен, если задание выйдет за её пределы.
- Ученик не может удалить свои попытки; преподаватель ставит только комментарий, не оценку.
- Удалить пользователя из программы нельзя.
- Иконки берутся из шрифта Windows; на Windows 10 используется Segoe MDL2 Assets — часть глифов может выглядеть иначе.

## 25. FAQ — частые вопросы

**Как хранится аудио в базе?**
В базе — только описание файла (таблица `Audio`: путь `StoredPath`, название, расшифровка, размер, длительность, владелец).
Сам звук — файлом в `%LOCALAPPDATA%\TutorSpace\media\<владелец>\<GUID>.<ext>`. Упражнение ссылается на клип через
`Exercises.AudioId`, ответ ученика — через `Answers.AudioId`, самопрезентация — через `AudioId` внутри `Weeks.IntrosJson`.

**Какой максимальный размер аудио?** 15 МБ. Запись с микрофона — до 5 минут (самопрезентация — 60 секунд).

**В каком формате пишется голос?** WAV, 16 бит, моно, 22 050 Гц, через Windows MCI (`winmm.dll`).

**Как узнаётся длительность загруженного файла?** Через MCI: файл открывается, запрашивается длина в миллисекундах.

**Где хранится выполнение задания?** В самой строке задания (`Tasks.IsCompleted`, `CompletedAt`, `MissionResponse`, `StudentComment`).

**Где анкета и серия ученика?** В строке ученика в `Users` (`Interests`, `Level`, `OnboardedAt`, `CurrentStreak`…).

**Где посещения?** В `Users.VisitsJson` — список дней с числом входов.

**Где вопросы к созвону, оценки уроков, самопрезентации?** JSON-колонки недели: `Weeks.CallQuestionsJson`, `LessonReviewsJson`, `IntrosJson`.

**Где журнал правил?** В `Rules.FiresJson`.

**Где шаблоны недель?** В `Weeks`, это недели с `IsTemplate = 1`, без ученика (`TutorStudentId` пусто), с автором `TutorId`.

**Где ключ к пропускам?** В `Exercises.ConfigJson` (`Template` и `Blanks`), он получается разбором текста `{{…}}` при сохранении.

**Где ответы ученика?** Таблица `Answers`, каждая попытка отдельной строкой, сами ответы — в `AnswersJson`.

**Как «подгружаются» данные на экран?** Каждый экран в `Reload()` запрашивает свежие данные у сервиса
(EF Core, `AsNoTracking`, `Include` связанных таблиц, `AsSplitQuery`) и перестраивает элементы. После любого действия —
снова `Reload()`. Вкладки ученика строятся заново при каждом открытии.

**Кэшируются ли данные?** Нет. Каждая операция — свой контекст базы, открылся/закрылся.

**Как создаются таблицы?** `Database.EnsureCreated()` по модели из `AppDbContext` при запуске. Миграций нет.

**Что будет со старой базой (18 таблиц)?** Программа её не изменяет: сообщит, что база от старой версии, и попросит указать другое имя базы — новая создастся автоматически.

**Как подключиться к другому серверу?** Окно входа → «Настройки подключения к БД», или файл `settings.json`,
или переменная `TUTORSPACE_DB`.

**Почему в базе не все связи каскадные?** SQL Server запрещает несколько каскадных путей к одной таблице и каскад
таблицы на саму себя. Эти ссылки обнуляет код в `AppDbContext.SaveChanges` (в той же транзакции).

**Как хранятся пароли?** PBKDF2-SHA256, 100 000 итераций, соль 16 байт: `pbkdf2$100000$соль$хэш`.

**Можно ли восстановить пароль ученика?** Нет, только задать новый: «Сбросить пароль».

**Логин чувствителен к регистру?** Нет.

**Почему ученик не видит задания?** Неделя не опубликована, день ещё не наступил, ученик отключён, или это неделя
другого преподавателя.

**Когда открывается задание?** В свой день: понедельник недели + номер дня + перенос заморозкой.

**Как проверяются пропуски?** Без учёта регистра, лишних пробелов, знаков препинания по краям, с любым из вариантов через `|`.

**Сколько попыток даётся?** Сколько задал преподаватель; по умолчанию у голосовых 3, у остальных без ограничений.

**Когда ученик видит ключ/пример ответа?** Только после своей первой попытки.

**Что такое `<<word>>`?** Подстановка слова из словаря ученика в текст вопроса (ещё и `<<translation>>`, `<<example>>`).

**Как работает правило «повторить через N дней»?** Создаёт копию задания на дату «сегодня + N» в нужной неделе
(при необходимости — новая неделя «Повторы»), пишет запись в журнал.

**Срабатывают ли правила по расписанию?** Нет, только когда ученик отправил попытку или закрыл задание.

**Как считается серия?** +1 за день, в который что-то выполнено, если вчера тоже; пропуск дня — снова с 1; заморозка серию сохраняет.

**Сколько заморозок?** Одна в неделю, только сегодняшний урок, на один день, не в воскресенье.

**Почему нельзя сдвинуть неделю?** Какое-то задание вышло бы за понедельник/воскресенье — сдвиньте его отдельно.

**Что значат кнопки повторения слов?** Снова — сегодня ещё раз; Трудно — чуть больше текущего интервала; Хорошо — 1 → 6 → × лёгкость;
Легко — как «Хорошо» × 1.3. Интервал от 180 дней — «выучено».

**Какое слово дня видит ученик?** Самое свежее (на сегодня или раньше) от любого его активного преподавателя.

**Можно ли у ученика несколько преподавателей?** Да, через «Прикрепить». Каждый видит только свои недели.

**Как перенести программу на другой компьютер?** Собрать/скопировать программу, перенести базу (бэкап SQL Server) и папку `media`.

**Где лог ошибок?** Отдельного лога нет — ошибки показываются окнами.

**Работает ли без SQL Server?** Нет, нужен SQL Server (подойдёт бесплатный Express или LocalDB).

**Есть ли в программе логин/пароль по умолчанию?** Нет. Первый преподаватель регистрируется сам.

**Что открывает кнопка «Смотреть видео»?** Ссылку в браузере по умолчанию. Для тезисов — с нужной секунды отрезка.

**Можно ли указать ссылку на файл на компьютере?** Нет, только веб-адреса `http/https` — ради безопасности.

**Почему в интерфейсе нет эмодзи?** Так задумано: строгий стиль, иконки — из системного шрифта Windows.

**Как поменять цвета?** В `UI/Theme.xaml` (ключи `Primary`, `AppBackground`, `Success`, `Danger`…).

**Нужно ли ставить .NET?** Нет, релизный `TutorSpace.exe` самодостаточный — .NET встроен в файл.

**Чем HTML-демо отличается от программы?** Данные в браузере вместо SQL Server; аудио живёт, пока открыта вкладка;
логика и экраны — те же.

## 27. Выпуск релиза

**Текущий релиз: 1.0.0** — `Выпуск\TutorSpace\TutorSpace.exe` (≈ 66 МБ).

| Параметр | Значение |
|---|---|
| Конфигурация | `Release` (оптимизация включена, отладочные символы не поставляются) |
| Платформа | Windows x64 (`win-x64`) |
| Формат | **один файл**, самодостаточный (`--self-contained`): .NET 10 и все библиотеки внутри, установка .NET не нужна |
| Иконка | `UI/app.ico` |
| Версия / продукт | задаются в `ivan.csproj` (`Version`, `Product`, `Description`, `Copyright`) |
| Языки ресурсов | только `ru` и `en` |

Команда сборки релиза (из папки проекта):

```
dotnet publish ivan.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o Выпуск/TutorSpace
```

**Что убрано из релиза по сравнению с разработкой:** кнопка и код демо-данных (с логинами `tutor / 1234`),
служебные «крючки» для автотестов (подмена даты, перехват окон сообщений), автоматическое удаление базы старого формата.

**Установка у пользователя:** нужен запущенный SQL Server (подойдёт бесплатный Express или LocalDB); скопировать
`TutorSpace.exe` в любую папку и запустить. **Обновление:** заменить `TutorSpace.exe` на новый — данные (база и папка
`%LOCALAPPDATA%\TutorSpace`) не затрагиваются. **Удаление:** удалить `TutorSpace.exe`, папку `%LOCALAPPDATA%\TutorSpace`
и, если данные не нужны, базу `TutorSpace` на SQL Server.

**Доступность:** у всех кнопок, пунктов меню, списка учеников и вкладок есть имена для экранного диктора
(Windows UI Automation), содержимое вкладок доступно диктору.
